# RFC 9857 - BGP-LS Advertisement of SR Policies

| Field | Value |
|-------|-------|
| **Title** | Advertisement of Segment Routing Policies Using BGP - Link State |
| **Authors** | S. Previdi, K. Talaulikar (Ed.), J. Dong, H. Gredler, J. Tantsura |
| **Date** | October 2025 |
| **Status** | Proposed Standard |
| **Link** | [datatracker.ietf.org/doc/rfc9857](https://datatracker.ietf.org/doc/rfc9857/) |

## Summary

[RFC 9514](rfc9514.md) lets a controller learn SRv6 **topology** (locators, SIDs) through BGP-LS. RFC 9857 adds the other half: the **state of SR Policies** instantiated on headends. Each SR Policy candidate path — whether configured locally, pushed via PCEP, or pushed via the BGP SR Policy SAFI — can be reported with its Binding SID, state, constraints, and segment lists, for both SR-MPLS and SRv6.

This matters when the headend does not speak PCEP (management-based PCE), when a parent PCE needs a global view from child PCEs, or when a service-placement system or NMS needs to see which policies exist and whether they are up. It closes the loop for the BGP SR Policy SAFI ([RFC 9830](https://datatracker.ietf.org/doc/rfc9830/)): controllers push policies with BGP and read their operational state back with BGP-LS.

The BGP-LS producer can be the headend itself or a PCE relaying what its PCCs report.

## SRv6-Specific Pieces

| Element | Detail |
|---------|--------|
| **SRv6 Binding SID TLV (1212)** | 128-bit BSID plus the *specified* BSID; flags B (allocated), U (specified BSID unavailable), F (fell back to dynamic) |
| **SRv6 segment types** | Type B (SRv6 SID), Type I (End SID by node address), Types J/K (End.X SID by adjacency, global or link-local) |
| **Behavior and structure** | The RFC 9514 SRv6 Endpoint Behavior TLV (1250) and SID Structure TLV (1252) can be attached as sub-TLVs to a BSID or a segment |

## Protocol-Origin Values

| Value | Meaning |
|-------|---------|
| 1 / 2 / 3 | PCEP / BGP SR Policy / Configuration (CLI, YANG, NETCONF) — reported by the headend |
| 10 / 20 / 30 | Same origins, reported by a PCE acting as the BGP-LS producer |

!!! warning "Common Pitfalls"
    - The NLRI reports state at **candidate-path** granularity; composite candidate paths are out of scope.
    - Large policy counts produce many BGP-LS updates. Check whether the platform lets you filter which policies are exported.
    - The Local Node Descriptor identifies the **headend**, even when a PCE is the producer — do not mistake it for the BGP-LS speaker.
    - Other TE path types (e.g., RSVP-TE LSPs) are handled by a separate draft, not this RFC.
