# RFC 9352 - IS-IS Extensions for SRv6

| Field | Value |
|-------|-------|
| **Title** | IS-IS Extensions to Support Segment Routing over the IPv6 Data Plane |
| **Authors** | P. Psenak, C. Filsfils, A. Bashandy, B. Decraene, Z. Hu |
| **Date** | February 2023 |
| **Status** | Proposed Standard |
| **Link** | [datatracker.ietf.org/doc/rfc9352](https://datatracker.ietf.org/doc/rfc9352/) |

## Summary

RFC 9352 defines extensions to the IS-IS routing protocol to support SRv6. These extensions allow IS-IS to advertise SRv6 SIDs, locators, and endpoint behaviors, enabling automated SRv6 deployment within an IGP domain.

## Key Concepts

### SRv6 Locator Advertisement

IS-IS advertises SRv6 locators as reachable IPv6 prefixes with additional SRv6-specific TLVs. This allows all routers in the IS-IS domain to learn:

- The SRv6 locator prefix for each node
- The SRv6 SIDs and their associated behaviors
- The algorithm used for path computation

### New TLVs and Sub-TLVs

| TLV/Sub-TLV | Description |
|-------------|-------------|
| **SRv6 Locator TLV (27)** | Advertises an SRv6 locator with its prefix and flags |
| **SRv6 End SID Sub-TLV (5)** | Sub-TLV of the Locator TLV; associates an End SID with a locator |
| **SRv6 End.X SID Sub-TLV (43)** / **LAN End.X SID Sub-TLV (44)** | Advertises adjacency-specific SIDs |
| **SRv6 SID Structure Sub-Sub-TLV (1)** | Describes the locator/function/argument split; carried inside the End, End.X and LAN End.X SID sub-TLVs |
| **SRv6 Capabilities Sub-TLV (25)** | Advertises SRv6 capabilities of a node |

### SRv6 SID Structure

The SID Structure sub-sub-TLV communicates how a 128-bit SID is divided:

```
|<-- Locator Block -->|<-- Locator Node -->|<-- Function -->|<-- Argument -->|
|<------- Locator Length (bits) -------->|
```

This allows other nodes, controllers and management systems to understand the structure of SIDs without pre-configuration. Per RFC 9352 Section 9, it is informational only and must not be used by transit nodes for forwarding.

### SRv6 Locator TLV Detail

The SRv6 Locator TLV (Type 27) structure:

| Field | Length | Description |
|-------|--------|-------------|
| Metric | 4 bytes | Route metric for the locator prefix |
| Flags | 1 byte | D-flag (leaking from L2 to L1) |
| Algorithm | 1 byte | IGP Algorithm (0 = SPF, 128-255 = Flex-Algorithm) |
| Loc-Size | 1 byte | Locator length in bits (1-128) |
| Locator | Variable | The SRv6 locator IPv6 prefix |
| Sub-TLVs | Variable | End SID sub-TLVs (each may carry a SID Structure sub-sub-TLV), Prefix Attribute Flags sub-TLV |

### SRv6 SID Structure Sub-Sub-TLV Detail

| Field | Length | Description |
|-------|--------|-------------|
| Locator Block Length (LBL) | 1 byte | Number of bits for the Locator Block (common across the domain) |
| Locator Node Length (LNL) | 1 byte | Number of bits for the Locator Node (per-node identifier) |
| Function Length (FL) | 1 byte | Number of bits for the Function (behavior-specific) |
| Argument Length (AL) | 1 byte | Number of bits for the Argument (optional, behavior-specific) |

!!! example "SID Structure Example"
    For the End SID `fcbb:bb00:1:1::` in the common F3216 format (block `fcbb:bb00::/32`, node `1`, so locator `fcbb:bb00:1::/48`, function `1`):

    - Locator Block Length = 32
    - Locator Node Length = 16
    - Function Length = 16
    - Argument Length = 0

    Locator length = 32 + 16 = 48 bits, and the SID uses 32 + 16 + 16 = 64 of its 128 bits; the rest is zero.

!!! warning "Common Pitfalls"

    **Locator Block Length vs Locator Node Length.** The Locator Block is the common prefix shared across the SRv6 domain (e.g., `fcbb:bb00::/32`), while the Locator Node is the per-node portion within the block. Together they form the full Locator. Confusing these two fields leads to incorrect SID resolution. The total Locator Length = Locator Block Length + Locator Node Length.

    **SID Structure mismatch causes silent failures.** If the SID Structure sub-sub-TLV values do not match the actual SID allocation on the advertising node, remote nodes will parse the SID incorrectly. For example, if a node advertises Function Length = 16 but actually uses 20 bits for the function, other nodes will compute wrong SIDs for VPN services.

    **Algorithm field must match Flex-Algorithm.** When advertising a locator under a Flex-Algorithm (algorithm value 128-255), the Algorithm field in the Locator TLV must match the Flex-Algorithm Definition advertised elsewhere in IS-IS (RFC 9350). A mismatch means the locator will not be used for that algorithm's path computation.

    **End.X SIDs are per-adjacency, not per-locator.** End.X SIDs are advertised in the Extended IS Reachability TLV (TLV 22 or TLV 222) as sub-TLVs of the adjacency, not as sub-TLVs of the Locator TLV. This is different from End SIDs which are sub-TLVs of the Locator TLV.

### Maximum SRv6 SID Depths (MSD)

Section 4 defines four SRv6 MSD types, advertised with the RFC 8491 MSD sub-TLVs (node MSD in the Router Capability TLV, link MSD in TLVs 22, 23, 25, 141, 222 and 223):

| MSD Type | Value | Meaning | If not advertised |
|----------|:-----:|---------|-------------------|
| SRH Max Segments Left | 41 | Largest Segments Left value in a received SRH that the node can process | 0 |
| SRH Max End Pop | 42 | Most SIDs in an SRH for which the node can apply the PSP or USP flavor | Node cannot apply PSP/USP (also if 0) |
| SRH Max H.Encaps | 44 | Most SIDs the headend can push in an SRH with H.Encaps | Only single-segment policies without an SRH (also if 0) |
| SRH Max End D | 45 | Most SIDs in an SRH when performing decapsulation (e.g. End.DT4, End.DX6) | Node cannot decapsulate if the outer header has an SRH (also if 0) |

Headends and PCEs use these values to avoid building segment lists that a node cannot process.

### Interaction with Flex-Algorithm

SRv6 locators can be associated with IS-IS Flex-Algorithm, enabling constraint-based path computation. Different locators can be advertised under different algorithms (e.g., shortest path, low latency, disjoint paths).

## Configuration Example (Cisco IOS-XR)

```cisco
router isis CORE
 address-family ipv6 unicast
  segment-routing srv6
   locator MAIN
  !
 !
!
```

## Configuration Example (Juniper)

```junos
set protocols isis source-packet-routing srv6 locator myloc end-sid fc00:0:2::1
```
