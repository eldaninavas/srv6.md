# RFC 9723 - BGP Colored Prefix Routing (CPR)

| Field | Value |
|-------|-------|
| **Title** | BGP Colored Prefix Routing (CPR) for Services Based on Segment Routing over IPv6 (SRv6) |
| **Authors** | H. Wang, J. Dong, K. Talaulikar, T. Han, R. Chen |
| **Date** | May 2025 |
| **Status** | Informational |
| **Link** | [datatracker.ietf.org/doc/rfc9723](https://datatracker.ietf.org/doc/rfc9723/) |

## Summary

RFC 9723 describes how to deliver **intent-aware (color-aware) SRv6 services across multiple ASes without any new BGP extension**. The trick is to put the intent into the locator: each PE splits its base locator into **sub-locators, one per intent** (low delay, high bandwidth, ...). These *Colored Prefixes* are advertised in plain BGP **IPv6 unicast (AFI/SAFI 2/1)** with a **Color Extended Community**.

Service SIDs are then allocated from the colored sub-locator that matches the service's intent — e.g., a low-latency VPN gets its End.DT4 SID from the low-delay locator. Service routes are advertised as usual ([RFC 9252](rfc9252.md), Option C, next hop unchanged) and need no color of their own. Ingress PEs and border routers simply do **longest-prefix match** of the service SID against the colored prefix, and resolve that route onto an intra-domain path for the tuple *(next hop, color)* — an SRv6 Policy, SRv6 Flex-Algo, or even an SR-MPLS/RSVP-TE LSP in MPLS transit domains.

Because the packet's destination is always the service SID, no inter-domain transport label or SID is needed, keeping encapsulation small.

## Example Allocation

| Prefix | Intent | Advertised with |
|--------|--------|-----------------|
| `2001:db8:aaaa:1::/64` | Base locator | No color |
| `2001:db8:aaaa:1:0000::/68` | Color 1 (e.g., low delay) | Color Extended Community C1 |
| `2001:db8:aaaa:1:1000::/68` | Color 2 (e.g., high bandwidth) | Color Extended Community C2 |
| ... up to `2001:db8:aaaa:1:f000::/68` | 16 intents total | ... |

## CPR vs Other Intent-Aware Approaches

| Approach | Signaling | Intent carried in | Border-node data plane |
|----------|-----------|-------------------|------------------------|
| **CPR (RFC 9723)** | Existing IPv6 unicast SAFI + Color EC | Service SID's locator | Plain IPv6 forwarding (re-encapsulate per domain) |
| **BGP-CAR** | Separate SAFI | Locator prefix | Similar, with dedicated SAFI |
| **BGP-CT** | Classful Transport SAFI | Additional transport SID | SRv6 operation similar to label swap |
| **Inter-domain SR Policy** | Controller / BSID | Segment list | Policy stitching |

!!! warning "Common Pitfalls"
    - CPR assumes all participating ASes are one **trusted domain** (same operator or a formal trust model). Colored locators are ordinary IPv6 unicast routes, so boundary filters must keep them from leaking.
    - **Disable aggregation** for IPv6 unicast routes carrying a Color Extended Community; otherwise the base locator swallows the colored sub-locators.
    - If one intent uses different color values in different ASes, borders must rewrite the Color EC according to a consistent mapping policy. The same colored prefix appearing with two colors is a misconfiguration.
    - Domains that do not support CPR fall back to best-effort resolution — the service still works, but the intent is not honored in that AS.
    - With `5f00::/16` ([RFC 9602](rfc9602.md)) blocked by default at boundaries, explicitly permit the colored prefixes in use within the trusted domain.
