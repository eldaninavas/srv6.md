    SRv6 for AI¶

    SRv6 now runs inside some of the largest AI training networks in the world. OpenAI, Microsoft and Oracle use static SRv6 uSID source routing in their GPU fabrics through MRC, with no BGP in the backend. Meta and Alibaba use SRv6 traffic engineering to connect AI clusters across sites. The SRv6 for AI section covers who runs it, how it works, how to design a fabric, and the standards behind it.

    SRv6 SID Decoder¶

    Paste any SRv6 SID or uSID container and see what every bit means: Locator-Block, node, function and argument, F3216 uSIDs, the end-of-container, and a hop-by-hop walk of the RFC 9800 shift-and-forward. It also looks up any IANA behavior codepoint, and every decode has a link you can share.

    SRv6 (IPv6 Segment Routing) in a Nutshell¶

    SRv6 (Segment Routing over IPv6) is a networking technology that uses IPv6 itself to steer and program traffic. The source router writes the path into the packet as an ordered list of IPv6 addresses called SIDs, and the network follows it without MPLS, LDP or RSVP-TE. The complete guide is in What is SRv6?.

    It is also written Segment Routing v6, SR v6 or IPv6 Segment Routing. Technically, SRv6 is the IPv6 data plane of the Segment Routing architecture (RFC 8402). It encodes forwarding instructions directly in IPv6 packet headers. Instead of relying on MPLS labels and signaling protocols like LDP or RSVP-TE, SRv6 uses native 128-bit IPv6 addresses as Segment Identifiers (SIDs) to program network paths and behaviors.

    The source node builds an ordered list of segments that defines the packet's path and the processing at each hop. The active segment sits in the IPv6 destination address; when there is more than one, the rest travel in a Segment Routing Header (SRH) — and with uSID compression a whole path often fits in the destination address with no SRH at all. Transit routers simply forward on the destination address. This enables traffic engineering, VPN services, fast reroute and service function chaining on a plain IPv6 network.

    Why choose SRv6 over traditional MPLS?

    • Simplified operations — No more MPLS label management, LDP, or RSVP
    • Native IPv6 — Uses the existing IPv6 data plane with no overlays
    • Network programmability — Define custom network behaviors with SRv6 functions (End, End.DT4, End.DX6, etc.)
    • Scalability — 128-bit SID space supports massive networks and micro-segmentation
    • Unified data plane — Single protocol stack for transport, VPN, and TE services

    The trade-offs, with real header overhead numbers, are in SRv6 vs MPLS.
